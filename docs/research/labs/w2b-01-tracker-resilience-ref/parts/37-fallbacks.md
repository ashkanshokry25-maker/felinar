### F8. Tracker-less signalling: Nostr relays pass every test and are in no block list; public MQTT brokers work but are weaker than assumed `[DESIGN-CRITICAL for the "second discovery plane"]`

Updates earlier F18/F19 (re-measured 2026-10-17 21:12-21:27Z).

**Nostr (Trystero's default strategy).** Ephemeral-event round trip as Trystero does it (BIP-340-signed kind 2xxxx event with an `x` tag, REQ filter, expect `OK` and an echo; `probes/results/nostr-mqtt-roundtrip-2026-10-17.txt`):
- **11 of 12 relays passed** with no auth, payment or PoW: `nos.lol` (connect 538 ms / OK 119 / echo 210), `relay.damus.io` (209 / 62 / 88), `relay.primal.net` (488 / 120 / 206), `relay.nostrmap.net`, `0x-nostr-relay.fly.dev`, `relay.bullishbounty.com`, `relay.piazza.today`, `relay.nostr.dev.br`, `offchain.pub`, `nostr.mom`, `relay.snort.social` (answered "ephemeral: will not be stored"). WebSocket connect 209-573 ms, OK 54-145 ms, echo 88-211 ms.
- **`purplepag.es` refused the event: `blocked: kind 27929 is not allowed`** - kind-allow-listing relays exist; a pinned list must be probed with the real kind range, not just NIP-11.
- **Independent liveness evidence (NIP-66):** `relay.nostr.watch` stores kind-30166 monitor events from 10-20 independent monitors (20 monitor announcements seen). For the 14 relays I looked up, 13 had a monitor report from the previous 3.5 hours; `rtt-open` between 44 and 1,966 ms depending on monitor location; all but one advertise `!auth !payment !pow` (**`nostr.wine` requires payment**); `relay.nostr.band` has had **no monitor event since 2026-02-06** (cause unknown). The older HTTP API `api.nostr.watch/v1/*` returned 502 today; the monitoring data now lives on Nostr itself (`probes/nip66-relay-liveness.mjs`).
- **Not in any list I checked** (F2): neither browser nor DNS lists contained any of these relays.
- **Trystero 0.26.0 (2026-10-04) is still the latest**; its 0.25.4 (2026-08-30) notes read "Reduced signaling traffic across all strategies. Rooms retain their fast startup announcement burst, then switch to a slower steady cadence", "Torrent now honors tracker-requested announcement intervals", and "rate-limited relays are backed off, incompatible relays are dropped, and the default relay list has been pruned"; the default relay lists were pruned or replaced in 0.20.1 (2025-02), 0.21.8 (2025-09), 0.23.0/0.23.1 (2026-03/04), 0.25.4 and 0.26.0: **about five list changes in twenty months, so budget for churn** (pin more than you use, probe at boot, rotate).

**MQTT over wss.** With names resolved through DoH, all four Trystero defaults completed CONNECT/SUBSCRIBE/PUBLISH/echo: `broker.emqx.io:8084` (connect 84 ms, echo 17 ms), `broker.hivemq.com:8884` (419 / 93), `test.mosquitto.org:8081` (351 / 86), `public.cloud.shiftr.io` (419 / 106). **Two of the four hostnames are on mainstream DNS block lists** (`broker.emqx.io` and `broker.hivemq.com` in HaGeZi Light/Multi/Pro/Pro++/Ultimate; HiveMQ also in HaGeZi TIF and BlockListProject malware; my own resolver sinkholed `broker.hivemq.com` to `0.0.0.0` and first produced a false "down", see Gotchas) and all four operators call these brokers test/community infrastructure ("do not abuse or rely upon it for anything of importance" - Mosquitto; "not intended for private or production data" - HiveMQ). Topics are world-readable.

**Verdict.** Use Nostr as the independent second plane (pinned list of at least 7 relays from the 11 that passed, probe at boot, join 5), keep MQTT only as a third, optional fallback, and run our own `@trystero-p2p/ws-relay` instance (Trystero 0.24.0+, defaults: `maxPayload` 1 MiB, 128 subscriptions per socket, limits added in 0.26.0) on the same box as the tracker if we want a plane we control. None of the planes authenticate peers: signalling content is attacker-controlled, so cap pending offers and validate every message (R8). SDP is end-to-end encrypted in Trystero with a key derived from appId + roomId, which a relay operator can re-derive; pass a `password` if SDP secrecy from relay operators matters.
**Confidence:** high for the measurements (re-runnable; raw output saved); medium for relay longevity (monitor data are claims by third parties; list churn is observed, not predicted).
