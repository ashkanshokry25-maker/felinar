### F9. Health monitoring: no mainstream free monitoring tier speaks the WebSocket tracker protocol, so use HTTP + heartbeat + one custom probe

**Claim.** Free and cheap uptime SaaS can watch the TLS/HTTP layer of our own tracker and the web seed, but none lists a WebSocket monitor type; the end-to-end check (upgrade + announce + offer relay) needs our own probe, scheduled somewhere that is not the tracker host, and reported through a dead-man's-switch heartbeat so that a dead checker is also an alert.

**What to run (all of it exists in the evidence folder):**
1. **Layer 1, host and process:** Prometheus scrapes `tracker.mjs` (`mwt_*`), Caddy (`caddy_http_*` on the admin endpoint) and node_exporter; alert rules in `monitoring/mwt.rules.yml` (down, restart loop, uncaught exception, event-loop lag > 100 ms, RSS, near connection cap, reject/refusal spikes, certificate expiry).
2. **Layer 2, external synthetic probe (the one that matters):** `probes/check_trackers.py --min-ok 3 --relay --heartbeat <url> wss://...` does DNS, TCP, TLS, upgrade, announce with `numwant: 0` (not `scrape`: openwebtorrent closes the socket on scrape) and optionally the 2-peer offer->answer relay, and pings a heartbeat URL only on success. Run it from cron on a different machine or from GitHub Actions (`monitoring/tracker-health.yml`) every 5-10 minutes; use UptimeRobot/Better Stack/Healthchecks-style *heartbeat* monitors so "the checker itself stopped" alerts too. It covers public trackers and ours with the same code.
3. **Layer 3, web seed and `.torrent` (plain HTTP):** an HTTP monitor with `Range: bytes=0-0` expecting `206` and `Content-Range`, plus a CORS check (`Access-Control-Allow-Origin`, `Access-Control-Allow-Headers` containing `range`, `Access-Control-Expose-Headers` containing `Content-Range`), for the first file and for `<ws base>/<name>.torrent` (needed for the `xs=` bootstrap, F10). Free HTTP/keyword monitors cover availability; the CORS/Range assertions need the custom probe `probes/check_webseed.py` (preflight with `Access-Control-Request-Headers: range, cache-control`, `Range: bytes=0-0` -> 206 + `Content-Range` + exposed headers, and for `.torrent` a plain GET that returns a bencoded dictionary; tested here against a good seed (pass) and a CORS-less seed (all checks fail); `--heartbeat` feeds the same dead-man's-switch monitors).
4. **Hostname hygiene:** daily CI run of `probes/filterlist-check/` against every hostname in `config.js` (F2).
5. **No client telemetry exists by design** (no backend). If we want field data, the cheapest honest options are an opt-in "copy diagnostics" button in the loader and the tracker's own aggregate counters (`mwt_*`); do not add third-party beacons.

**Public trackers are not ours to ping at high rate.** The soak probe in this wave used one connection per tracker per 5 minutes (about 4 short sessions per tracker per hour at most); keep CI cadence at 10 minutes or slower and use `numwant: 0` announces on random never-published info hashes.
**Confidence:** high for the vendor facts (read 2026-10-17; marketing pages can change), high that no WebSocket type is listed on those two pages, medium for blackbox behaviour (docs only).
