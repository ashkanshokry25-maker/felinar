## Reference tracker deployment (Caddy + hardened `bittorrent-tracker` + systemd + Prometheus)

Everything is in `docs/research/labs/w2b-01-tracker-resilience-ref/`. It is a **research artefact**: tested as listed below, not security-audited, and not wired into `tools/tracker.mjs` (that is a builder decision, recommendation R3).

```
internet --443/tcp,udp--> Caddy 2.11.7 (TLS, HTTP/2+3, ACME)  --127.0.0.1:8000--> tracker.mjs (Node 24, bittorrent-tracker 11.2.3 + guards)
                           |  /healthz, static answer, masked JSON access log            |  127.0.0.1:9464/metrics (Prometheus, loopback only)
                           +-- admin 127.0.0.1:2019/metrics (caddy_http_*)               +-- stdout JSON logs -> journald
```

**Configuration reference (`tracker.mjs`, environment variables, defaults in parentheses).** `HOST` (127.0.0.1), `PORT` (8000), `METRICS_PORT` (9464; 0 = off; always bound to 127.0.0.1), `ANNOUNCE_INTERVAL_S` (120; sent to clients as `interval`), `MAX_PAYLOAD` (65536), `MAX_OFFERS` (10), `MAX_SDP` (16384), `MAX_CONNECTIONS` (20000), `MAX_CONN_PER_IP` (200; offices and CGNAT share addresses, keep it generous), `CONN_RATE_PER_IP_PER_MIN` (120), `MAX_SWARMS_PER_SOCKET` (16), `MAX_SWARMS_TOTAL` (100000), `RATE_BURST` (40) and `RATE_PER_SEC` (5) per socket, `BUFFER_LIMIT` (262144; worst-case RAM is this times `MAX_CONNECTIONS`), `PING_INTERVAL_S` (30; 0 disables ping and the idle close), `IDLE_TIMEOUT_S` (330), `PEERS_PER_SWARM` (1000; library LRU), `PEER_TTL_S` (1200), `GC_INTERVAL_S` (60), `ALLOW_FILE` (none), `OPEN` (off; the process refuses to start with neither `ALLOW_FILE` nor `OPEN=1`), `ALLOW_ORIGINS` (empty = any), `ALLOW_SCRAPE` (off), `TRUST_PROXY` (on; trust the client-IP header only from a loopback peer), `TRUST_ANY_PROXY` (off; for platforms where the proxy is the only way in), `CLIENT_IP_HEADER` (x-forwarded-for; the **last** entry is used), `SHUTDOWN_SPREAD_MS` (5000), `LOG_LEVEL` (info).
**Metrics (`mwt_*`).** `connections`, `connections_opened_total`, `connections_closed_total{reason}` (client, error, going_away, ping_timeout, idle, backlog), `upgrades_refused_total{reason}` (origin, full, ip_connections, ip_rate, shutting_down, not_websocket), `messages_total{action}`, `messages_rejected_total{reason}`, `offers_received_total`, `answers_received_total`, `bytes_received_total`, `library_warnings_total`, `uncaught_exceptions_total`, `message_handle_seconds` (histogram), `swarms`, `peers`, `event_loop_lag_p99_seconds`, `build_info`, plus the standard process/GC/event-loop series.

**Runbook (condensed).**
1. *Provision:* Oracle Always Free A1 (home region; stateless security-list rules for 22/80/443, TCP and UDP 443) or any Ubuntu 24.04 VPS; DNS A/AAAA for a **neutral hostname** (`rtc.<domain>`; not `tracker`/`torrent`); CAA record.
2. *Install:* `deploy/cloud-init.yaml` shows Node 24.22.0 from the official tarball (verify the SHA-256), Caddy from the official apt repo, the `mwtracker` user, files under `/opt/magnet-tracker`, `/etc/magnet-tracker/env`, `npm ci --omit=dev --ignore-scripts`.
3. *Start:* `systemctl enable --now magnet-tracker caddy`; verify from another machine: `python3 -I probes/check_trackers.py --relay wss://rtc.<domain>`.
4. *Publish:* add `tr=wss://rtc.<domain>` first in the pointer, then the public trackers; put the site's `btih` and chain-room id in `ALLOW_FILE` (production) or run `OPEN=1` only for experiments.
5. *Observe:* Prometheus + rules; external probe every 5-10 minutes with a heartbeat monitor; daily hostname check (F2).
6. *Upgrade:* `systemctl restart magnet-tracker` drains in 5 s and exits 0 (clients with the stock reconnect return after 10 s + U(0, 5 min), with the reconnect shim of R4 after about a second); avoid `caddy reload` at peak (F5: closes all sockets in 71 ms, or after `stream_close_delay`); certificate renewal needs no reload.
7. *Incidents:* high event-loop lag -> check `rate(mwt_messages_total)` and `mwt_messages_rejected_total{reason}`, raise `RATE_*` only after identifying the sender; memory growth -> `closed_total{reason="backlog"}`, lower `BUFFER_LIMIT`; abuse -> set `ALLOW_ORIGINS`, switch from `OPEN=1` to `ALLOW_FILE`, put Cloudflare in front (note its unstated WebSocket idle timeout; the server ping handles it); crash loop -> `journalctl -u magnet-tracker`, `mwt_uncaught_exceptions_total`, and report the offending message shape upstream.
8. *Capacity:* 25 KiB RSS per socket (measured) plus 70 MB base: 20,000 sockets = 0.57 GB; egress per socket about 50 B/s at the stock 5 offers and 120 s, about 1 B/s with the adaptive policy of R5 (F7).
