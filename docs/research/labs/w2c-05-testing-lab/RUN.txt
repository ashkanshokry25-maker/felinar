w2c-05 testing lab (2026-10-17) - throwaway experiments behind docs/research/w2c-05-testing-qa-production.md
=========================================================================================================

Environment of the recorded results
  MacBook Air M3, macOS 27.0 (Darwin 27.0.0), Node v24.22.0 (official build at ~/.local/share/node/current),
  npm 11.19.1, Playwright 1.64.1 = chromium-1248 (Chromium 156.0.8078.4, also chromium_headless_shell-1248),
  webkit-2370 (WebKit 27.2), firefox-1555 (Firefox 157.0, does NOT launch on this macOS, see below).
  webtorrent 3.0.21, bittorrent-protocol 5.0.9, @thaunknown/simple-peer 10.1.2, node-datachannel 0.32.3 (project),
  fast-check 4.10.2 (installed in this directory only). LuLu (per-process firewall) was running.
  Other agents were using the machine at the same time, so wall-clock numbers can be noisy (ratios and counts are the point).

How to run
  cd docs/research/labs/w2c-05-testing-lab
  npm install --ignore-scripts          # fast-check only; node_modules is git-ignored
  ./run-all.sh                          # writes results-<date>.txt, 10-25 minutes depending on machine load
  node <script>.mjs                     # any single experiment (all are read-only on src/ and node_modules/)
  node npm-versions.mjs fast-check axe-core ...   # registry version + publish date lookups used for section 3

Prerequisites: the project's node_modules (playwright, ws, webtorrent, bittorrent-protocol, create-torrent,
node-datachannel) and browsers installed with `node node_modules/playwright/cli.js install chromium webkit firefox`.
Scripts import via ../../../../node_modules and ../../../../src, so keep this directory at docs/research/labs/w2c-05-testing-lab.

Caveats
  - Scripts were written for one-off measurement, not as product tests; timeouts are generous and some sleeps are long (blackhole runs wait 45-70 s).
  - Results come from one machine on one network; no NAT, TURN, cellular or phone hardware was involved.
  - webkit-*.mjs and engine-probe.mjs fail the WebRTC part on this machine (see F-B4); that is a result, not a script bug.
