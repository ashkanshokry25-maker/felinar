# w2a-04 experiments (drop-in embedded mode)

Test code and raw results behind `docs/research/w2a-04-dropin-embedded-mode.md`. Chromium 156.0.8078.4 and Playwright's
WebKit build (reports 27.2; NOT Safari: no ITP, no Lockdown Mode, page cache not enabled), macOS arm64, 2026-10-17.
Firefox could not be launched in this environment (Playwright Firefox 157 exits with "Could not find profile folder").

Run (Node >= 22; the project's `node_modules` provides playwright and bittorrent-tracker):

    export PATH=$HOME/.local/share/node/current/bin:$PATH
    cd docs/research/labs/w2a-04-experiment
    ln -s ../../../../node_modules node_modules          # reuse the project's dependencies
    mkdir -p www && cp ../../../../node_modules/webtorrent/dist/webtorrent.min.js www/wt.js
    node run-csp.mjs            # CHROMIUM_CHANNEL=shell for headless-shell (needed for cross-context WebRTC); BROWSER=webkit
    node run-ice.mjs            # does CSP connect-src restrict ICE/STUN?
    node run-bfcache.mjs        # back/forward cache vs WebSocket/WebRTC/Web Locks/IDB (needs full Chromium, not headless-shell)
    node run-sw.mjs             # SW scope rules and first-load semantics (+ navigation overhead on Chromium)
    node run-sw2.mjs 40 nf-i,idb-i,idbs-i,cache-i   # real cold starts, manifest read cost
    node run-locks.mjs chromium|webkit              # Web Locks leader hand-off across navigations
    node run-lock-bfc.mjs       # does a bfcached page starve the lock?
    node run-rc.mjs             # FetchEvent.resultingClientId
    node run-tag.mjs            # module-script tag reading and API availability
    node run-hcache.mjs         # force-cache retention of large files (PERSIST=1 for a persistent profile)

`www/big/*.bin` (1, 10, 50, 120 MB random files) are generated by `run-hcache` prerequisites and omitted here
(python3 -c "import os; open('f10.bin','wb').write(os.urandom(1048576)*10)").
Known harness limits: full Chromium in new headless mode could not connect WebRTC between two pages here, so end-to-end
WebTorrent-over-bfcache was not measured (only RTCPeerConnection loopback inside one page); `run-wt-bfc2.mjs` is that
unsuccessful attempt, kept for transparency.
