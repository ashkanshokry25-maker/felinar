felinar dev seeder

Seeds the site that tools/publish.mjs wrote, from the web seed directory of the dev server (/ws/summary.json and /ws/<name>/...), with the same name and piece length, so the infohash is the one in the pointer. It is served by tools/dev-server.mjs --dev --webseed <publish out dir> at /_dev/seeder.html; tools/demo.mjs opens it in a headless Chromium. Query parameters: ?tr=<ws url> (repeatable) replaces the tracker list, ?summary=<url> and ?base=<url> change where the summary and the files come from.

v0.3 (V03-DESIGN-REVIEW 2.8.6, MF-50): ?persist=1 keeps the pieces in the browser profile (IndexedDB, on disk) with the loader's own chunk store (/_dev/store-idb.js, needs --dev) instead of tab memory, so a restart keeps seeding from disk: when the profile already holds every piece of this infohash, the page adds the torrent (/ws/<torrent>) against that store and verifies it instead of fetching the files again. Run it in a browser with a profile directory (tools/live.mjs launchBrowser({ profileDir })); a fresh context has nothing to keep.
